# 成都理工大学校史馆·青藏高原滑轨屏联动播控系统

---

## 项目概述

**项目名称：** 成都理工大学校史馆·青藏高原滑轨屏联动播控系统  
**技术栈：** React、TypeScript、Vite、Python、FastAPI、WebSocket、UDP/TCP、PyInstaller；配套中控为Tauri、Rust、SQLite  
**项目角色：** 独立开发，负责播放器前后端、机械协议适配、数字人及中控接口、外置内容配置和现场联调交付。

面向校史馆青藏高原科考展项，独立开发将竖屏媒体、实体滑轨、数字人Host和远程中控联动的本地系统。以统一运行时管理展示内容与机械位置，通过WebSocket同步媒体状态，经本机UDP调用厂家软件驱动滑轨，提供独立全屏与Host托管两种运行方式。完成边移动边播放、四点位及回原点、混合内容巡展和配置维护；四点位与回原点已获现场确认，后续巡展及受保护远程入口具备本机验证，现场长时运行仍待复核。

## 核心亮点（简历要点）

**① 以统一业务运行时连接触屏、数字人和中控，分离内容位置与真实机械状态。**

- FastAPI统一接受页面、Host和中控命令，内部按业务点位映射媒体与绝对毫米坐标；调用方不用理解电机报文或维护坐标。
- 将 `currentPointId`、`targetPointId`、`displayPointId` 分别用于已到达位置、运动目标和当前内容，准确表达“画面已切换、滑轨仍移动”的中间态。
- 通过WebSocket广播状态，前端与各控制端复用点位和播控逻辑；配置加载后服务即可ready，硬件在后台限时初始化并独立报告错误，避免电机离线拖垮Host页面展示。

**② 为媒体和机械建立独立完成条件，实现边移动边播放、到位不重播的巡展调度。**

- 选点后先启动目标内容，再异步移动滑轨；到位回执只更新机械状态，不重新加载或播放视频，保留移动期间的暂停、停止操作。
- 以 `mediaSessionId`、`playbackRevision` 及媒体源校验浏览器反馈；前端检查真实 `ended` 和播放位置，后端拒绝旧会话、旧修订和重复结束事件。
- 巡展必须同时满足“机械到位＋视频真实结束”才进入下一项；图文或无视频项从到位后开始计时，支持当前点位续展、往返、循环及回原点结束，单点重播不重复驱动电机。
- 停止巡展只取消后续调度，以 `asyncio.shield` 保留已经发出的移动；机械异常或媒体错误中止巡展，不自动重发物理动作。

**③ 封装可替换的机械协议适配层，依据现场试验校准方向并限制重复运动风险。**

- `MotorProvider` 隔离Mock、TCP和UDP实现；现场使用UDP `127.0.0.1:53500`对接同机厂家控制软件，由其连接伺服控制器。
- 根据现场小距离正向试验修正早期资料中的负坐标，采用原点0与1600、3200、4800、6400 mm绝对坐标；四点位与回原点随后由用户确认可控。
- 每条UDP请求使用独立套接字并串行发送，隔离迟到回包；MOVE超时不重试，以免响应丢失时重复驱动。匹配 `OK:MOVE` 坐标后才确认到位。
- 区分停止视频、停止巡展及厂家STOP软停；回原点使用 `MOVE 0`，不调用会改变参考零点的 `ZERO`。软件软停不等于硬件急停。

**④ 将AI应用接入与局域网控制分权，统一动作目录、幂等执行和机械互锁。**

- 本机8000端口服务页面、WebSocket和WakeFusion；8001独立网关只开放中控白名单，并校验安装级Bearer密钥、来源网段及明确的跨域来源。
- WakeFusion提供健康、状态、动态动作目录和执行接口；动作描述及关键词可编辑，`actionsHash`通知目录变化；校验请求ID和幂等键并缓存结果，避免重复调用造成副作用。
- Host Token、管理密码和中控密钥独立；中控只通过业务HTTP接口控制点位，不接触UDP或毫米坐标。
- 配套中控在机械动作前重新查询状态，对移动中、巡展中、目标未清空、异常或状态字段不完整进行互锁；设备锁限制连点，滑轨动作排除通用场景自动重试。

**⑤ 外置内容与展示配置，使素材逐步补齐、单点演示和多点巡展使用同一程序。**

- 点位ID、顺序、坐标、标题、视频、海报、背景及数字人关键词由JSON配置；接口ID与文件名解耦，点位能力不因素材暂缺而删除。
- 提供 `demo / compact / visit` 展示模式及访客控制显隐，可在仅有p04素材时固定展示并隐藏点位栏，同时保留中控及四点能力。
- 管理员支持素材重扫、展示模式和触控按钮配置，配置通过临时文件替换保存；诊断信息集中到管理员面板，不占据观众主页面。
- 增加播放诊断：记录媒体尺寸、缓冲余量、readyState、总帧/丢帧和最近事件，用于区分媒体读取、解码与状态同步线索，不把单一指标当成卡顿根因。

**⑥ 适配2160×3840竖屏与数字人叠加，完成可回退的离线交付。**

- 使用固定9:16媒体卡片及数字人安全区，避免视频全屏遮挡Host形象；根据媒体容器宽度调整播放控件，保持触摸区域与短横向音量条可用。
- 以PyInstaller交付服务，Host使用无浏览器启动脚本；独立模式等待健康检查后启动Edge kiosk，使用专用浏览器目录，便于脱离Host排查。
- 通用包排除现场视频、密钥和浏览器缓存；前端局部更新保留旧页面并核验哈希，正式升级逐项迁移现场配置和媒体。
- 历史回归覆盖Mock、假UDP控制器、媒体会话、双入口HTTP及实际交付程序；四点位和回原点的现场确认与后续软件模拟验证分别记录。

## 总简历推荐写法

**项目总览：** 独立开发青藏高原滑轨屏联动系统，以React、FastAPI、WebSocket及UDP连接触屏、数字人、中控与厂家软件，完成四点位及回原点现场控制，支持边移动边播放和自动巡展。

- **异步状态协同：** 分离到达位置、运动目标和展示点位，以媒体会话/修订号过滤迟到事件；巡展同时等待到位与真实播完，到位不重播、暂停不误推进。
- **协议与控制边界：** 封装Mock/TCP/UDP适配，独立套接字隔离回包，物理动作不自动重试；双端口、独立密钥和中控状态互锁限制误触与重复运动。
- **配置与交付：** 点位、坐标、内容和展示模式外置，支持动态动作目录与素材重扫，提供Host托管/独立kiosk及保留现场媒体的更新包。

两页总简历优先前两条；本项目用机械与媒体双状态体现工程深度，不重复其他数字人项目的通用对话能力。

## 技术细节备忘（面试参考，不写入简历）

- **异步不是状态混用：** 从原点到最远点为6400 mm；四个展示点之间最大跨度为4800 mm。播放先开始不代表机械已经到位，设备反馈和展示反馈必须分开。
- **控制风险：** UDP响应丢失不能证明动作未执行；停止巡展不会中断在途运动，STOP只按厂家语义软停并保持使能。用户界面“急停”字样不能当安全认证。
- **AI接入范围：** 本项目实现数字人Host动作接口、关键词和嵌入布局，不包含语音模型或LLM训练。动态动作下标依赖当前启用目录；幂等缓存不跨进程持久化。
- **内容与解码：** 音量、静音和拖动进度为本地页面能力，目前没有远程音量API。浏览器输出依赖页面实际运行；不应同时启动Host和独立页面产生多个反馈源。
- **性能与验证：** 本机Range读取、软件解码速度和模拟控制器结果不能证明现场4K无丢帧。播放诊断用于定位线索，不宣称已根治现场卡顿；p03背景缺失、数字人真实叠加、8001网络/防火墙、V1.1.7长时运行仍待现场核验。
- **文档新旧：** README开头仍写“硬件协议未实现”，旧接入说明仍为负坐标；当前源码、正坐标配置及中控交接较新，不能机械照抄旧说明。1.1.3手册只记录正负方向试验，后续交接已补充四点位和回原点确认。
