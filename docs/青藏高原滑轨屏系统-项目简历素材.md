# 成都理工大学校史馆·青藏高原滑轨屏联动播控系统

---

## 项目概述

**项目名称：** 成都理工大学校史馆·青藏高原滑轨屏联动播控系统

**技术栈：** React、TypeScript、Vite、Python、FastAPI、Uvicorn、WebSocket、UDP/TCP、PyInstaller；配套中控使用 Tauri、Rust、SQLite

**项目角色：** 全栈开发 / 现场系统集成

面向校史馆青藏高原科考展项，设计并实现集竖屏媒体播放、实体滑轨控制、数字人嵌入和远程中控于一体的本地化播控系统。系统采用浏览器展示层与统一运行时协同架构，通过 WebSocket 同步媒体状态，经本机 UDP 对接厂家控制软件，并向数字人 Host 和局域网中控提供分权 API。完成四点位及原点联动、移动与播放并行、自动巡展、竖屏触控界面和免安装交付，现场已验证四点位与回原点控制。

---

## 核心亮点（简历要点）

> 以下为简历可选择性使用的项目要点，每条以“总结 + 细节展开”形式组织，细节部分用于面试时自我阐述。

**① 设计“数字人 / 中控 / 浏览器 / 厂家软件”多端协同架构，以统一运行时收敛媒体与机械状态**

- 将系统拆分为数字人 Host、本机 Web 页面、远程中控入口、统一业务运行时和厂家电机服务，避免各控制端直接理解毫米坐标与底层命令。
- 使用 `currentPointId`、`targetPointId`、`displayPointId` 分离已到达位置、运动目标和当前展示内容，解决“页面已切换但滑轨仍在移动”的状态表达问题。
- 通过 FastAPI 提供业务 API、WakeFusion 数字人动作接口和 WebSocket 状态广播，使触屏、语音数字人和中控平板复用同一套点位与播控逻辑。
- 将业务就绪状态与硬件在线状态解耦，配置加载后即可向 Host 提供页面和健康检查，避免电机离线导致数字人界面持续 503、无法展示。

**② 构建媒体会话同步机制，实现长距离移动与视频并行且到位不重播**

- 将点位切换设计为“立即切换内容并开始播放，同时异步移动滑轨”，消除长距离移动结束后才播放造成的等待体验。
- 引入 `mediaSessionId` 和 `playbackRevision` 标识媒体会话与显式播控修订，避免机械状态广播触发视频重复加载、跳回开头或覆盖暂停状态。
- 浏览器仅在会话、版本、媒体源均匹配时上报 `ended/error`，隔离迟到结束事件，防止旧视频反馈错误推进新点位巡展。
- 自动巡展同时等待“滑轨到位 + 视频真实结束”；无视频或图文展项则在到位后按配置停留，再继续折返并最终回原点。

**③ 基于现场实测封装安全的 UDP 滑轨协议，处理方向、超时与重复动作风险**

- 对接与播放器同机运行的厂家控制软件，通过 UDP `127.0.0.1:53500` 封装 `PING / STATUS / MOVE / STOP`，由厂家软件间接驱动伺服电机。
- 通过小距离正负方向试验纠正早期口述的负坐标误差，最终采用 0、1600、3200、4800、6400 mm 正绝对坐标并完成现场四点位及回原点验证。
- 每条 UDP 请求使用独立套接字隔离迟到回包；MOVE 超时不自动重发，避免“电机已移动但响应丢失”时重复驱动造成机械风险。
- 区分停止视频、停止巡展和机械软停三种语义；回原点使用 `MOVE 0`，禁止误用会改变参考零点的 `ZERO` 指令。

**④ 建立本机与局域网双入口的安全控制边界，并在中控侧增加状态互锁**

- 本机页面与数字人接口仅监听 `127.0.0.1:8000`，远程中控通过独立 `0.0.0.0:8001` 网关访问，避免直接向局域网暴露管理页、素材和 WebSocket。
- 为 8001 接口加入安装级 Bearer 密钥、来源网段和路由白名单，数字人 Token、管理员密码与中控密钥相互隔离。
- 配套中控通过 HTTP 空请求体调用四点位、播放、暂停、停止、回原点和巡展接口，不直接发送厂家 UDP，也不保存毫米坐标。
- 中控在机械动作前重新查询状态，对移动中、异常、巡展中、目标未清空和状态不明确等情况执行互锁，并限制连点和自动重试。

**⑤ 以外置配置驱动点位、内容与展示模式，兼顾临时单点演示和后续多点扩展**

- 将点位 ID、顺序、毫米坐标、标题、视频、海报、背景和数字人关键词集中到 JSON 配置，素材文件名与 API 点位标识解耦。
- 提供 `demo / compact / visit` 展示模式及访客按钮显隐配置，在只有 p04 视频时可固定展示并隐藏点位栏，同时保留四点联动和中控能力。
- 自动巡展支持从当前点位继续、到末点折返、回原点停止；素材缺失不会删除点位能力，便于后续逐步补齐视频或图文资料。
- 管理员面板提供素材重扫、展示方式、控制按钮显隐和播放诊断，运维信息不暴露在观众主页面。

**⑥ 面向 2160×3840 竖屏和数字人叠加完成触控 UI 与可回退交付**

- 针对现场竖屏及竖向视频设计固定 9:16 媒体卡片，右侧预留数字人安全区；不使用视频全屏，保证数字人形象持续可见。
- 根据视频容器实际宽度适配播控栏，将播放、暂停、停止和短横向音量条保持在清晰触控区域，静音以红叉反馈，最小触控目标保持 44 px。
- 使用 PyInstaller 交付免安装 Web 服务，启动脚本采用 ASCII + CRLF，避免 Windows 中文环境下的批处理编码问题。
- 通用包排除现场视频、密钥和浏览器缓存；纯前端调整采用带哈希校验和旧页面备份的小补丁，降低现场升级范围并支持快速回退。

## 技术细节备忘（面试参考，不写入简历）

### 为什么这样设计？

- **为什么不是 Tauri 单体桌面应用？** 数字人团队要求 Host 内嵌浏览器并在网页上层渲染真实数字人，因此改用本地 FastAPI Web 服务；同时保留独立 Edge kiosk 启动，便于脱离数字人单独调试。
- **为什么中控不直接控制电机？** 中控只表达“去哪个业务点位”，播放器负责坐标映射、素材播放、机械互锁和厂家协议。这样点位距离或控制器协议变化时，不需要同步修改中控页面和数据库。
- **为什么需要三个点位状态？** 内容可先切换，机械随后到达；若只用一个“当前点位”，页面、高亮、巡展和机械反馈会相互覆盖。
- **为什么播放与移动并行？** 四个点位最大距离达到 6400 mm，等待到位后播放会产生明显空窗；并行后仍通过媒体会话标识保证到位事件不会重置视频。
- **为什么分成 8000 和 8001？** 8000 服务数字人和本机页面，功能面较大；8001 只提供中控白名单接口并强制 Bearer，降低局域网暴露面。

### 遇到什么问题？

- 早期健康接口将硬件连接作为 ready 条件，现场电机未通时持续返回 503，数字人 Host 因此拒绝加载整个页面。
- 厂家早期口述坐标需要取负，实际安全距离测试发现 `MOVE 100` 就是正 100 mm；错误取负会让滑轨朝相反方向运动。
- 初版流程等待滑轨到位才播放，长距离移动期间用户只能等待；机械状态更新还可能引起视频重载或暂停状态丢失。
- UDP 动作可能已经执行但回包丢失，若按普通网络请求自动重试，会带来重复运动风险。
- 竖屏媒体卡片宽度有限，常驻音量百分比和图标挤压文字按钮，现场出现文字溢出与控件截断。

### 如何解决？

- 将运行时 ready 改为配置加载完成即就绪，硬件在后台限时初始化，并单独报告机械状态与错误。
- 使用小距离安全试验验证方向，以现场证据修正坐标模型，并将坐标外置到点位配置。
- 通过媒体会话 ID、播控修订号和有效 ended 反馈建立浏览器媒体状态机，到位事件只更新机械状态。
- UDP MOVE 采用单次发送、不自动重试和独立套接字；中控侧再叠加状态查询、机械互锁和防连点。
- 使用 CSS 容器查询按媒体卡片宽度响应式布局，移除冗余按钮图标与常驻百分比，并用多组竖屏/横屏尺寸做浏览器回归。

### 取舍是什么？

- 业务 ready 与硬件在线解耦后，页面可在硬件故障时正常展示，但调用方必须继续查看 `motorState/error`，不能把 `ready=true` 当作电机可用。
- UDP MOVE 不重试提高机械安全性，但网络响应丢失时需要人工结合厂家软件和状态查询确认真实位置。
- 浏览器负责真实视频播放和 ended 反馈，能准确推进巡展，但正式运行时应避免同时打开多个业务页面，以免产生重复音频和多个反馈源。
- 通用安装包不携带现场视频和密钥，交付更安全、体积更小，但升级时必须显式迁移 `content/videos`、`remote-control.key` 和现场自定义配置。
- 当前已确认四点位和回原点现场可控；V1.1.7 的数字人叠加触控、长时间 4K 播放及 p03 缺失背景仍应在下一轮现场验收中单独确认，不能将离线测试描述为完整现场验收。
