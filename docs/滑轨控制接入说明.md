# 滑轨控制接入说明

## 先确认当前状态

当前 `config/machine.json` 的 `provider` 为 `mock`。这是开发安全模式：页面、点位切换和轮播会模拟移动，但**不会向滑轨、电机或串口发送任何字节**。

切勿在未核对控制器通信方式、限位与急停状态前，把 `provider` 改为真实硬件模式。

## 当前程序的信号链路

```text
数字人 / 触屏页面
  -> POST /api/control/points/{pointId}/activate
  -> SceneService 停止当前视频
  -> 电机 Provider 按 pointId 读取 positionMm
  -> 发送移动命令
  -> 控制器确认后，页面切换并播放对应视频
```

点位绝对坐标只在 `config/points.json` 的 `positionMm` 维护。例如 `p02` 的 `positionMm: 1200` 表示滑轨目标绝对坐标 1200 mm；修改点位数量或顺序不会改变该规则。

## 已实现的网口模式（TCP / UDP）

若现场控制器确认使用随附通讯文档中的网口协议，可在 `config/machine.json` 中配置：

```json
{
  "provider": "tcp",
  "network": {
    "host": "控制器IP",
    "port": 8080,
    "sharedKey": "如控制器要求则填写"
  }
}
```

UDP 模式将 `provider` 改为 `udp`。程序发出的每条网口报文都以 `\r\n` 结尾；如果设置了 `sharedKey`，会在命令前附加 `KEY <sharedKey>;`。

| 动作 | 当前实现的命令 | 预期响应 |
| --- | --- | --- |
| 连通性检查 | `PING` | `PONG` |
| 读取状态 | `STATUS` | 含 `RDY=...`、`ALM=...` 的状态字段 |
| 移动到点位 | `MOVE <positionMm>` | 以 `OK:MOVE` 开头 |
| 停止 | `STOP` | 以 `OK:STOP` 开头 |

“回原点”不是控制器归零命令；它会移动到 `points.json` 的 `homePointId` 对应毫米位置，避免误用会改变坐标系的 `ZERO` 类命令。

## 串口控制器：当前尚未接入

当前后端只实现 `mock`、`tcp`、`udp` 三种 Provider，**没有 `serial` Provider**。如果现场控制器通过 USB/RS-232/RS-485 串口控制，不能直接改配置上线；否则程序不会发送正确的串口帧。

接入串口前必须从设备厂商或通讯文档确认以下内容，再实现对应的 `SerialMotorProvider`：

1. COM 端口号、波特率、数据位、校验位、停止位、流控。
2. 移动到绝对毫米坐标的帧格式、帧头/帧尾、校验算法和编码。
3. 成功、到位、运动中、报警和急停的返回帧。
4. 原点、限位、复位是否会重置坐标系。
5. 命令确认是“已接受”还是“已到位”。若只是已接受，必须轮询到位信号后再播放视频。

## 现场上线步骤

1. 断开机械负载或将滑轨置于安全测试状态，确认急停有效。
2. 填写每个点位的 `positionMm`，逐点用低速/空载校验实际位置。
3. 仅配置网口模式时，先在管理员面板执行硬件 Ping；成功后再测试单点移动。
4. 核对控制器“到位”定义后，测试“移动完成后开始播放视频”的时序。
5. 最后才启用自动巡展。

> 重新提供运动控制 PDF 或串口调试日志后，才能按真实帧格式完成串口 Provider；在此之前请保持 `provider: "mock"`。
