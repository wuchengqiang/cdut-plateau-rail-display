# 滑轨控制接入说明

本程序按 [运动控制通讯文档(1).pdf](../运动控制通讯文档(1).pdf) 的信捷伺服 TCP/UDP 协议设计。控制器已确认使用网口，不需要串口接入。

## 上线前只需填写的配置

编辑 `config/machine.json`：

```json
{
  "provider": "tcp",
  "network": {
    "host": "192.168.x.x",
    "port": 8080,
    "sharedKey": ""
  }
}
```

当前 `provider` 保持为 `mock`，因此开发预览不会发送任何真实控制信号。现场确认控制器 IP 后，再改为 `tcp`；只有确实无法使用 TCP 时才改为 `udp`。PDF 指明 TCP 才支持实时位置推送 `WATCH`。

`homePosition`、`positionsMm` 会由 `config/points.json` 自动生成：每个点位的 `positionMm` 就是滑轨目标绝对坐标（毫米）。不要手工维护两份坐标。

首次交付时四个 `positionMm` 都是 `null`，表示尚未校准；这不是 0 mm。`mock` 模式仍可正常预览，但 TCP/UDP 模式会拒绝向未校准点位发送移动命令，避免误动作。现场按实际 `POS:...mm` 返回值填写即可：

```json
{
  "id": "p02",
  "title": "地质巡测",
  "positionMm": 1234.5
}
```

## 实际信号时序

```text
数字人 / 触屏：POST /api/control/points/p02/activate
程序 -> 控制器：MOVE 1200\r\n
控制器：运动、位置稳定、COIN/RDY 到位
控制器 -> 程序：OK:MOVE 1200
程序：切换 p02 页面并开始播放 p02 视频
```

PDF 明确 `MOVE <mm>` 会等待运动到位才返回。因此视频不会在“刚开始移动”时播放；只有收到 `OK:MOVE` 后才播放。

## 使用的协议命令

| 用途 | 发送 | 期待响应 |
| --- | --- | --- |
| 连通检查 | `PING\r\n` | `PONG` |
| 移动到点位 | `MOVE <毫米坐标>\r\n` | `OK:MOVE <毫米坐标>` |
| 软停止 | `STOP\r\n` | `OK:STOP` |
| 查询状态 | `STATUS\r\n` | `OK:POS=...;ALM=...;RDY=...` |
| TCP 实时位置 | `WATCH 100\r\n` | `OK:WATCH 100ms`，随后 `POS:12.34mm` |

程序启动 TCP 连接后会自动执行 `PING`、`STATUS`、`WATCH 100`。状态推送和命令响应会在同一连接交错到达，程序已按 `POS:` 与 `OK:`/`ERR:` 前缀区分。

若控制器设置了共享密钥，在 `sharedKey` 填入后，程序会自动把每条命令发送为 `KEY <密钥>;MOVE 1200\r\n` 这类格式。

## 现场测试顺序

1. 先记录控制器 IP；确认电脑与控制器处于同一网段。
2. 将 `provider` 改为 `tcp`、填入 `host`，保留端口 `8080`；如厂家启用密钥，再填写 `sharedKey`。
3. 在管理员面板对应的硬件接口执行 Ping，确认收到 `PONG`。
4. 用现场控制软件把滑轨停到每个展示点，记录 TCP `WATCH`/`STATUS` 返回的 `POS:...mm`，逐项填入 `points.json` 的 `positionMm`。
5. 在空载和急停有效的前提下，先测试一个最近点位；确认 `OK:MOVE` 后视频才开始。
6. 全部点位校准完成后，最后测试自动巡展。

## 安全边界

- “回原点”会移动到 `homePointId` 对应的绝对毫米坐标，绝不发送 `ZERO`；`ZERO` 会把当前位置清零，不能用于常规回原点。
- `STOP` 与 `JOG STOP` 是保持伺服使能的软停，不等于断电。
- 运动中若收到 `ERR:MOVE_FAIL`、报警或超时，程序会停止视频切换并显示错误，需现场检查限位、伺服和网络。
