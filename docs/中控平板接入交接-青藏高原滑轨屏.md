# 中控对接播放器：青藏高原滑轨屏交接说明

> 对象：负责中控软件的开发人员 / Codex 任务。
> 本文只交接播放器的控制接口，不交接电机坐标、厂家协议或视频文件路径。
> 项目为青藏高原滑轨屏，不是70周年播放器。`V1.1.5` 包包含受保护中控入口、展示模式、回原点巡展和软停接口；视频素材由现场另行复制，不包含在通用包内。
> **2026-09-11 更新：中控改用独立 HTTP 端口8001，并携带中控专用 Bearer 密钥。此前文档的远程8000方案作废；8000保持本机数字人/页面专用，厂家53500也不是中控接口。**
> 目标主机 `192.168.1.105`；现场须更新为V1.1.5，防火墙及实际中控网络仍需部署验证。中控已确认支持POST空请求体、GET查询及Bearer鉴权，不降低鉴权要求。

## 1. 要实现什么

用中控平板的按钮，代替用户在滑轨播放器页面上点击对应按钮。

控制链路：

```text
中控平板 / 其他电脑点按钮
    ↓
访问滑轨屏主机 192.168.1.105 上的播放器 Web API
独立中控入口 TCP 8001：校验来源地址、密钥和允许的接口
    ↓
播放器执行自己的业务逻辑
    ├─ 播放、暂停或停止现场视频
    └─ 切点时，由播放器通知厂家软件移动滑轨
```

**中控只负责发“去点位1”“暂停视频”等动作，不负责计算坐标、选择视频文件或发送电机命令。**

播放器继续维护点位与视频的对应关系、机械坐标、厂家通信及到位判断。数字人仍可显示在播放器之上，中控不需要模拟鼠标点击，也不需要数字人语音来中转这些动作。

## 2. 四个点位按钮

| 中控按钮 | 点位 ID | 调用播放器的接口 |
| --- | --- | --- |
| 点位1 · 高原启程 | `p01` | `POST /api/control/points/p01/activate` |
| 点位2 · 地质巡测 | `p02` | `POST /api/control/points/p02/activate` |
| 点位3 · 冰川源区 | `p03` | `POST /api/control/points/p03/activate` |
| 点位4 · 高原守望 | `p04` | `POST /api/control/points/p04/activate` |

点击任一按钮后，播放器自行切换对应内容并立即播放视频或展示图文，同时执行对应滑轨移动；到位后不重新开始视频。

- 一次点位激活请求即可，不需要再连发“播放”。
- 不传坐标，不传视频路径，不通过视频文件名定位。
- 点位名称可配置；中控可通过 `GET /api/points` 获取 JSON 数组，使用 `id`、`title`、`navLabel`、`order` 生成按钮。返回的其他内部配置不需要中控维护。
- 接口使用稳定 ID，不使用数字人动作目录中的数字下标。
- 若中控按钮排列与实体滑轨保持一致，从左到右显示“4、3、2、1”；按钮与 ID 的对应关系不变。
- 当前已放入点位1视频，点位2～4尚缺视频素材。新源码对缺少视频的点位展示配置图片、标题和文字；不能把受理结果当作视频成功播放的证明。

## 3. 播控按钮

| 中控按钮 | 调用播放器的接口 | 实际作用 |
| --- | --- | --- |
| 播放 / 继续 | `POST /api/control/play` | 播放或继续当前视频，不主动移动机械 |
| 暂停视频 | `POST /api/control/pause` | 暂停视频，不停止电机 |
| 停止视频 | `POST /api/control/stop` | 停止视频、回到开头，不是机械急停 |
| 回原点 | `POST /api/control/home` | 由播放器停止巡展及视频，并执行回原点；中控需二次确认 |
| 开始自动巡展 | `POST /api/control/carousel/start` | 新源码：有视频等播完且到位；无视频/图文到位后统一停留，再切下一点 |
| 停止自动巡展（可选） | `POST /api/control/carousel/stop` | 停止后续自动切点，不会立即停止已经发出的机械移动 |
| 紧急停机（软停） | `POST /api/control/emergency-stop` | 停止巡展、取消本程序在途移动，并向厂家软件发送 `STOP`；保持伺服使能，不是断电急停 |

第一阶段优先做“四个点位 + 播放、暂停、停止”。回原点和软停单独放置，软停必须二次确认。厂家文档中的 `STOP` 是按减速度停下但保持使能，不能作为人身安全急停或替代厂家控制软件的使能/急停。巡展接口可按原路径开发；现场替换为含本次修改的新版后再启用启动按钮。新源码支持有视频、无视频、图文混合巡展。

**音量、静音、拖动播放进度，目前只有页面本地功能，没有远程 HTTP API。** 中控暂不做成可用按钮；如需要，另外提出播放器接口扩展，不能猜测路径或直接控制厂家软件。

## 4. 请求方式与地址

所有控制请求统一使用 **POST，空请求体**，无需传入视频、坐标或其他参数；所有中控请求（包括读取状态、点位列表）都必须带 `Authorization: Bearer <中控密钥>`。

中控设备不在滑轨屏主机上，因此正式接入应使用主机局域网 IP，而不是让中控填写 `127.0.0.1`。

地址和端口必须区分：

| 项目 | 地址/端口 | 中控是否使用 |
| --- | --- | --- |
| 滑轨屏主机 IP | `192.168.1.105` | 是 |
| 受保护的中控 HTTP API 端口 | `8001`（TCP） | 是，调用本文接口，要求中控密钥及来源检查 |
| 数字人/本机页面端口 | `127.0.0.1:8000`（TCP） | 否，继续只供本机页面和数字人Host |
| 厂家软件 UDP 端口 | `53500` | 否，仅由播放器内部使用；不是 HTTP API |

**中控不能向厂家端口 53500 发送本文的 HTTP 请求。** 那样既不是调用播放器，也不会自动执行播放器的视频联动。

新版部署后的中控地址（现场旧包不具备此入口）：

```text
http://192.168.1.105:8001
```

中控调用点位1的格式：

```http
POST http://192.168.1.105:8001/api/control/points/p01/activate
Authorization: Bearer <部署后取得的中控密钥>
```

**只替换为包含本次修改的新版后，启动程序才会创建8001入口。当前已发出的旧包不会因改文档或放行防火墙而获得此功能。**

新版同一程序维护两个独立监听入口，共享一个播放器及电机运行状态：

- `127.0.0.1:8000` 保留原有本机页面、管理员、内部播放反馈和数字人标准接口；不改Host的 `pageUrl`，不向局域网开放它。
- `0.0.0.0:8001` 是独立中控入口，只允许本文的点位、播控、巡展、状态和点位列表。`0.0.0.0` 是绑定地址，中控实际填写 `192.168.1.105`。
- 中控入口即使从本机访问也要求密钥；不会因为传入 `Host: localhost` 或 `X-Forwarded-For` 而免验证。
- 默认允许 `127.0.0.1/32` 和 `192.168.1.0/24` 来源，可改成实际中控后台或设备的单个IP。使用后台代理时，这里填后台IP，不是平板IP。
- 不开放远程首页、管理员、视频素材、`/api/media/events`、`/ws` 或 `/api/wakefusion/v1/*`。8001不是供浏览器展示播放器页面的地址。
- 控制请求只允许POST，远程不能沿用旧接口的GET控制方式。读取状态和点位列表使用GET。
- 中控不索取管理员密码2468或数字人Host Token；二者都不是中控接口密钥。
- 端口8001若冲突，程序启动会明确报错，不复用未知服务、不绕过鉴权。需要改中控端口时，在配置文件修改并同步中控地址、防火墙规则，不改8000或厂家端口。

### 密钥如何取得

新版第一次启动且启用中控入口时，自动生成独立随机密钥，保存在：

```text
app\runtime\config\remote-control.key
```

用记事本打开，将整行内容填入中控后台或原生客户端的“接口密钥”配置；文件内容不含引号。按双方确认，中控可以将密钥持久化入库或纳入其受控配置，安全存储、权限、备份和升级保留由中控侧负责，播放器不限制对方的存储实现。密钥不要写在URL、公开交接文档、公开源码或日志里。本文和通用安装包不放真实密钥。

播放器不会因中控升级而自动轮换密钥。播放器升级时保留现场 `remote-control.key`，中控存储的原值就继续有效；若播放器端文件丢失后重新生成，需同步更新中控保存的值。密钥“入库”不代表可省略请求头，Bearer鉴权仍然强制执行。

请求示例（`<中控密钥>` 是占位说明，实际必须替换）：

```http
GET http://192.168.1.105:8001/api/status
Authorization: Bearer <中控密钥>
```

### 平板是网页时

推荐“平板网页 → 中控自己的后台 → 播放器8001”，密钥保存在中控后台；后台可以在另外一台电脑，不要求装在滑轨主机。

原生平板客户端直接通过HTTP调用即可。若确需浏览器跨域直连，必须在 `remote-control.json` 的 `allowedOrigins` 中配置准确来源（如 `http://192.168.1.120:3000`），不能填通配符；OPTIONS预检不执行动作，真正请求仍需密钥。默认 `[]` 不接受跨域网页来源。HTTPS网页直连HTTP内网入口还可能被浏览器拦截，优先使用中控后台代理；不要把密钥写死到公开前端代码。

HTTP用于受限可信内网，传输不是加密的；不得将8001映射到公网。需要跨网时另行配置受保护的加密通道或HTTPS网关。

## 5. 如何判断操作结果

读取状态：

```http
GET /api/status
```

中控后台建议每秒查询一次，再把状态显示在平板上。

点位请求受理示例：

```json
{
  "success": true,
  "accepted": true,
  "scene": "p01",
  "message": "Scene p01 accepted"
}
```

判断规则：

- 同时检查 HTTP 状态与响应体，不能只看到 HTTP 200 就认为成功。
- `success=true`：应用接受/处理了请求；`accepted=true` 不等于已经到位。
- `accepted=false`：该点已在执行中或应用认为当前已在该点，属于无操作结果，不保证重新播放；继续播放使用专门的播放接口。
- `success=false` 或 HTTP 错误：显示失败/忙碌，不能继续盲发。
- `401`：中控密钥缺失或错误；`403`：来源、网页Origin或接口不允许；`405`：请求方法错误。鉴权/来源失败不执行动作。
- 请求超时：结果未知，可能已经执行。**不自动重发动作，只查询状态。**

状态主要看以下字段：

| 字段 | 中控如何使用 |
| --- | --- |
| `displayPointId` | 当前展示内容，用于高亮对应视频按钮 |
| `targetPointId` | 正在前往的目标，有值时不再提交新的机械动作 |
| `currentPointId` | 应用上次确认的机械点位 |
| `motorState` | `initializing` 连接中、`moving` 移动中、`arrived` 已到位、`error` 异常 |
| `playbackState` | `playing/paused/stopped` 为播控状态；新增 `ended` 表示已收到视频结束反馈，`showing` 表示无视频/图文展示 |
| `carouselMode` | 是否处于自动巡展 |
| `error` | 错误详情，供中控提示和排查 |
| `mediaError` | 视频读取或解码错误；出现时巡展停止排程，不自动跳过或重发移动 |

对一次新切点，等待“当前点位等于目标、目标字段清空、机械状态为 arrived”再显示已确认到位。应用启动时的初始点位不是自动实测位置的证明。

`playbackState=playing` 只是播放器后台要求播放，不代表浏览器一定有画面或声音；素材缺失、浏览器静音、缓冲和解码问题仍需实际画面验证。

## 6. 实施与验收要求

1. 中控在平板或其他电脑，目标主机为 `192.168.1.105`。部署新版后，放行受限TCP8001，携带中控密钥先请求远程 `GET /api/status`；不能把厂家服务可达当作播放器 API 可达。
2. 平板按钮只调用上述播放器接口，绝不向厂家软件发命令。
3. 防连点；移动中、初始化中或状态不明确时，禁止新的点位、回原点和启动巡展。暂停/停止视频仍可独立使用。
4. 回原点和软件软停都需二次确认，并避免与其他移动并发；停止视频、停止巡展都不能当作机械急停。软停请求超时后只查询状态，不自动重发。
5. 同一时间避免中控与数字人同时下发机械动作；当前没有完整的跨控制端控制权仲裁。
6. 现场保持实际播放器页面运行：Host 内嵌页面或独立页面二选一。只开后端服务不会输出视频。
7. 用户已确认现场四个点位及回原点都能正常控制，本次检查不要求为此重复现场移动测试。巡展新增的调度、停止和故障逻辑在开发电脑用 mock 检查，绝不发送真实动作。
8. 新增远程入口仍需从实际中控设备验证网络、权限和接口返回；可先只读检查，不必为网络测试移动滑轨。网络连通和安全确认后，再按需要确认实际画面响应。
9. 新巡展、受保护中控入口及软件软停包含在V1.1.5中；未修改现场防火墙或做实际平板网络联调。音量仅限页面本地触控，未提供中控接口。模拟及交付程序回归通过不等于现场长时间运行和浏览器播放效果已经验证。

## 7. 新巡展规则与验证（V1.1.5，2026-09-13）

**中控接口不变。巡展排程全部由播放器负责，中控不写计时器切点、不上报视频结束、不直接控制电机。**

| 情况 | 新源码实际规则 |
| --- | --- |
| 从原点启动 | 先到点位1，默认 `1 → 2 → 3 → 4 → 3 → 2 → 1 → 0`，确认到隐藏原点后自动巡展结束 |
| 已在展示点启动 | 从当前点开始；当前视频正在播放则接着播，暂停则恢复，已结束/停止则重新播放。例如在2启动：`3 → 4 → 3 → 2 → 1 → 0` |
| 有视频 | 移动时立即播放，必须等“真实视频结束反馈 + 滑轨确认到位”两个条件都满足才切下一点，不额外停留12秒 |
| 无视频或图文 | 到位后才开始计时，统一停留 `config/app.json` 的 `carouselDwellSeconds`，默认12秒，然后进入下一点 |
| 暂停/停止视频 | 不视为播放完；视频点不会自动进入下一点。播放/继续后仍等视频结束；不影响当前机械动作 |
| 停止巡展 | 只停止后续排程，当前已下发移动继续完成，当前视频不被暂停；不是急停 |
| 无结束反馈 | 保留当前点等待；未打开页面、被浏览器阻止播放、暂停或卡缓冲都不会按固定时长跳过视频 |
| 移动失败/丢失到位回执 | 立即退出巡展并保留错误，不再自动重复移动；确认硬件状态后由人处理 |
| 视频读取/解码失败 | 收到页面错误反馈后退出巡展，不擅自跳过。已发出的移动不因此急停 |

视频缺失与图文由播放器配置自动判断，仍建议补充合适图片与文字。增加、替换素材或修改类型后重启播放器；配置详情供播放器维护者参考《自动巡展规则与配置.md》，中控无需维护。

验证范围：9项内存模拟巡展回归、配置校验、网页媒体结束反馈单元检查、真实 HTTP 请求的模拟服务回归及既有 UDP 假控制器测试。覆盖先播完/先到位、图文停留、混合巡展、往返与循环、暂停停止、迟到重复反馈、停止巡展、故障不重发。所有测试使用 mock 或本机临时假控制器，没有联系现场厂家软件，也没有下发真实滑轨动作。

原先“跳过点位1”“失败后重复下令”问题已在V1.1.4修复；V1.1.5补齐单点巡展回原点、静态演示与软件软停。**V1.1.3及更早安装包仍是旧逻辑。** 现场部署新版并确认远程入口后启用巡展。现场四个坐标及回原点已由用户确认，本次无需为软件逻辑排查重新测量坐标；真实浏览器、素材和长时间运行尚不能只凭模拟断言全部通过。

## 8. 可直接发给中控项目 Codex 的任务说明

> 请在现有中控项目对接“青藏高原滑轨屏播放器”。中控运行于平板或其他电脑，调用 http://192.168.1.105:8001 ，所有请求携带 Authorization: Bearer <中控密钥>。双方已确认兼容POST空请求体、GET查询及Bearer鉴权，保留8001受保护接口。密钥从首次启动生成的app/runtime/config/remote-control.key取得；允许中控侧持久化入库以便升级保留，存储安全由中控负责，不放URL或公开源码。播放器升级保留原密钥文件即可继续使用原值，不自动轮换。8000保持数字人本机专用，厂家UDP53500也不使用。四个点位p01～p04使用POST /api/control/points/{id}/activate，另提供播放/继续、暂停、停止、开始/停止巡展、回原点和POST /api/control/emergency-stop（软件软停，需二次确认）；GET /api/status和/api/points同样携带密钥。中控不保存坐标、不维护视频路径、不连接厂家软件、不写轮播计时器。播放器按 `1→2→3→4→3→2→1→0` 自动巡展；有视频等视频播完且到位，无视频/图文则到位后统一停留；异常不重发。接口路径不变，旧文档远程8000地址作废。网页平板优先经中控后台代理，默认不允许跨域直连。读取状态、区分受理与到位、防连点；401/403/405要提示而非重试动作。兼容playbackState新增ended/showing。音量、静音、进度接口尚未提供。自动测试只用mock。

## 9. 新版现场配置与只读连通检查

当前源码 `config/remote-control.json` 的默认内容（打包后位于 `app/runtime/config/`）：

```json
{
  "enabled": true,
  "host": "0.0.0.0",
  "port": 8001,
  "allowedClients": [
    "127.0.0.1/32",
    "192.168.1.0/24"
  ],
  "allowedOrigins": []
}
```

- `enabled=false` 时不启动中控监听，数字人/独立页面仍能使用。旧配置缺少该文件时也保持本机模式。
- `allowedClients` 默认网段方便现场初次联调，确定中控来源后建议收紧为实际IP；不同网段的合法中控需要同步调整配置与防火墙。
- 修改监听、来源或跨域配置后重启程序，不能仅刷新页面。`app.json` 的 `apiHost` 仍须为 `127.0.0.1`，不要改成 `0.0.0.0`。
- 首次启动生成密钥，不自动放行防火墙。本次没有在开发电脑开启对外端口；测试使用临时回环端口和模拟电机。

部署顺序：

1. 取得包含本次修改的新版。先停止旧程序，备份原配置、视频/图片和已有 `remote-control.key`，再更新程序；不要无备份直接删除旧app。
2. 通过Host的 `start.bat` 或独立的 `start-standalone.bat` **二选一启动一次**，两个模式都由同一启动器创建两个入口，不再额外启动一份播放器。命令行直接运行旧的 `uvicorn app.main:app` 不会创建中控入口。
3. 在主机记事本打开 `app/runtime/config/remote-control.key`，将整行内容安全交给中控维护者。
4. 在可信现场网络下，确认Windows网络配置为“专用”，由管理员PowerShell执行下列防火墙规则。实际来源不在此网段时先修改为正确中控IP；这里只给指令，程序不会自动执行：

```powershell
New-NetFirewallRule -DisplayName "Rail-Central-TCP-8001" -Direction Inbound -Action Allow -Protocol TCP -LocalPort 8001 -RemoteAddress 192.168.1.0/24 -Profile Private
```

不要放行厂家端口来替代本规则，也不要为了连通关闭整个防火墙；已有同名规则时检查/更新，不重复创建。

5. 在滑轨主机先做本机中控入口只读检查。下面路径以 `C:\数字人` 为例，按实际安装位置修改：

```powershell
$railKey = (Get-Content -LiteralPath 'C:\数字人\app\runtime\config\remote-control.key' -Raw).Trim()
$railHeaders = @{ Authorization = "Bearer $railKey" }
Invoke-RestMethod 'http://127.0.0.1:8001/api/status' -Headers $railHeaders
Remove-Variable railKey, railHeaders
```

6. 在中控后台/设备配置 `http://192.168.1.105:8001` 和密钥，用其HTTP客户端请求 `/api/status`、`/api/points`。两项都是只读，不移动滑轨。未带密钥返回401表示入口有响应，但尚未授权；超时则检查程序是否新版、是否启动、端口、防火墙、网段和来源配置。
7. 网络与鉴权确认后再由人在场时验证一个播控动作；真实移动需现场安全确认。已测好的四个机械坐标不需要因新增入口重新测量。

重新部署时保留现场 `remote-control.key`，中控不必重新配密钥。需要轮换密钥时先停程序，移走旧密钥文件后重启生成新值，再同步更新中控；旧值立即失效。生成的真实密钥不能放进公共仓库或通用安装包，打包时须排除 `config/*.key`。

入口回归涵盖配置校验、密钥持久化、来源/伪造头过滤、接口白名单、跨域预检、端口冲突阻止启动，以及双端口HTTP模拟联动。数字人和中控密钥不能互用。交付程序使用隔离副本和本机假UDP控制器验证，不连接现场厂家软件，不修改实际防火墙。具体构建与回归记录见包内release-info.json及verification.json。
