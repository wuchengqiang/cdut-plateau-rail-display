# 滑轨屏 TCP 实机版现场更新步骤

交付版本：2026-09-10。应用 ID：`cdut-slider-screen`；WakeFusion V1.1 服务档。

## 本包已配置

- 已启用真实 TCP：`app/runtime/config/machine.json` 中 `provider` 为 `tcp`。
- 控制器地址：`192.168.1.104:8080`；SharedKey为空。
- 原点：0 mm；点位1～4：-1600、-3200、-4800、-6400 mm。
- 已包含点位1视频 `app/runtime/content/videos/p01.mp4`，约2分21秒。
- 点位2～4保留配置和移动能力，但还没有对应视频，首次验证使用点位1。
- 管理员密码：2468。
- 当前界面会裁切竖屏视频上下画面，尚未调整为完整竖屏展示。

厂家原始协议支持TCP和UDP，端口默认8080；本版使用TCP的WATCH位置反馈。MOVE收到到位回执后才播放视频。本包配置已就绪不等于已验证现场控制器能够连接或真实行程正确。

## 现场操作

1. 关闭 WakeFusion Host。备份原 `app` 文件夹，以及里面现场修改过的配置和素材。
2. 将压缩包内的 `app` 文件夹复制到 Host EXE 同级目录。不要把旧版 `_internal` 与新版混合，也不要把旧版mock配置覆盖回来。
3. 确保厂家控制软件/网络服务已运行，驱动连接正常；部署电脑能够访问 `192.168.1.104:8080`。该地址是厂家网络控制服务的地址，单有电机驱动器通电并不足以提供API。
4. 只启动数字人 Host，让它自动运行 `app/start.bat` 并注入Token。不要先单独启动业务EXE或开发服务占用8000端口。
5. 现场有人观察滑轨且行程内无障碍时，先说“切换到高原启程”。滑轨应移动到-1600 mm，等待到位后播放点位1视频。随后测试“暂停视频”“继续播放”“停止视频”。
6. 有需要再测试“回原点”；它会驱动滑轨回到0 mm。其余点位没有视频时先不启动自动巡展。

正确目录：

```text
<Host目录>\
├─ wakefusion-terminal-host.exe
└─ app\
   ├─ app.json
   ├─ start.bat
   └─ runtime\
      ├─ slider-screen-service.exe
      ├─ _internal\
      ├─ config\
      └─ content\videos\p01.mp4
```

主页面：`http://127.0.0.1:8000/?embed=1&avatarAnchor=right`。

动作描述配置页：`http://127.0.0.1:8000/subscriptconfig.html`；管理员密码2468。

Host读取 `app/app.json` 后自动加载标准接口和当前10项动作。按当前启用数组下标调用，不应把下标永久写死。

## 排查

网络测试（仅检测TCP端口，不移动）：

```powershell
Test-NetConnection 192.168.1.104 -Port 8080
```

页面显示并不保证电机已连接。程序在硬件连接失败时仍可提供页面，需检查错误信息和现场控制软件。日志位置：`<Host目录>\managed\logs\embedded-app.log`。

标准接口 `/api/wakefusion/v1/*` 需要Host注入的Bearer Token；管理员密码不等于这个Token。如果出现401，确认旧的手动启动服务已退出，并重新由Host拉起。

修改通信方式或IP端口后应重启Host。视频名称与点位名称可在 `app/runtime/config/points.json` 修改；更新程序前备份现场数据。

启动脚本使用纯ASCII命令、CRLF换行，新EXE也使用ASCII文件名，避免此前遇到的中文脚本编码问题。
