# 自动巡展规则与配置

2026-09-12，适用于当前青藏高原滑轨屏源码，非70周年播放器。本次展示方式、回原点巡展和软停改动尚未重新打包。

## 1. 播放规则

- 有视频：移动时就开始播放；视频结束且机械确认到位后进入下一点。谁先完成就等另一个，不重播、不额外停留。
- 无视频或配置为图文：移动时显示图片和文字；到位后统一停留，结束后进入下一点。
- 默认顺序：原点出发先到1，然后 `1→2→3→4→3→2→1→0`，确认到原点后自动巡展结束。只一个展示点时展示/播放一次后回原点。
- 已在展示点启动：当前视频正在播放则接着播，暂停则恢复，已停止或结束则重新开始；例如在2启动，顺序是 `3→4→3→2→1→0`。不重新前往当前点。
- 视频暂停或停止不算播放结束。继续播放并播完后才自动切点。
- 停止巡展只停止后续自动切点，当前移动、视频继续；不是机械急停。
- 移动失败或回执超时退出巡展，不能自动重试；视频文件存在但读取/解码失败也停止排程。已发出的移动不因此自动急停。
- 页面必须运行。没有收到真实结束反馈时一直保留当前视频点，不猜测时长、不超时跳过。

## 2. 统一停留时间

编辑 `config/app.json` 已有字段，只改数字，保留其余内容：

```json
"carouselDwellSeconds": 12
```

单位为秒，必须是大于0的数。只用于无视频/图文点，开始计时的时间是确认到位之后，不是开始移动时。

## 3. 展示方式：明日静态演示与后续参观

编辑 `config/app.json` 的 `presentation`。默认已是明日演示配置：机械静置在p4更美观的实景，页面仍展示唯一视频所在的p1内容。

```json
"presentation": {
  "mode": "demo",
  "demoRestPointId": "p04",
  "demoContentPointId": "p01"
}
```

- `demo`：隐藏底部1～4点位栏、隐藏标题点位编号，禁用左右滑动和半透明切换箭头；适合明日静态演示。
- `compact`：隐藏底部点位栏和标题编号，但保留视频左右滑动及半透明左右箭头；适合后续资料尚未完全公开时。
- `visit`：恢复当前完整参观界面：底部点位栏、标题编号和左右滑动均可用。
- `demoRestPointId` 是机械要停的位置；`demoContentPointId` 是静态页面展示/播放的内容点。二者可不同，当前为“机械停p4、播放p1”。两个ID都必须是已启用且可见的点位。

管理员面板可以直接切换三种方式。静态演示模式下的“前往p4演示位置”需要二次确认，停止巡展后才发送移动；到位后程序自动恢复 `demoContentPointId` 的视频/图文，不会再把机械p4误当成媒体p4。**只改配置或刷新页面不会让滑轨自动移动。**

## 4. 每个点位的内容类型

编辑 `config/points.json` 对应点位，保留原有 `id`、名称、顺序、坐标等字段。

有视频时（以下是需要合并的字段示例，不是整个点位或配置文件）：

```json
{
  "contentType": "video",
  "videoPath": "content/videos/p01.mp4"
}
```

`contentType` 不填默认就是 `video`。路径是播放器根目录下的相对路径，只使用 `content` 目录内文件；文件名不必叫p01，以配置路径为准。文件不存在或 `videoPath` 为空时自动按无视频点处理，后端状态为 `showing`。文件是否可解码由浏览器实际反馈，不靠扩展名保证。

图文点示例（合并到对应点位，不覆盖其他字段）：

```json
{
  "contentType": "imageText",
  "videoPath": "",
  "imagePath": "content/images/p02.jpg",
  "contentText": "这里填写该阶段的图文介绍。\n这里是第二段。"
}
```

`contentType=imageText` 时即使保留视频路径也不会播放视频。`imagePath` 不填使用该点的 `backgroundPath`；`contentText` 不填则只展示图片及现有标题、简介。图片自行放入配置路径，正文是纯文本，不执行HTML。这里是单张图片加文字展示，不是多页图文编辑器。

保存UTF-8 JSON。更换素材或类型后重启播放器，或停止巡展及媒体后通过管理员重新加载配置并刷新页面。不要在运行中的巡展直接修改类型。

## 5. 接口不变

中控仍只调用播放器：

```http
POST /api/control/carousel/start
POST /api/control/carousel/stop
```

空请求体，不传停留时间、坐标或视频名称。具体规则在播放器内部升级。数字人的既有动作索引和请求标准不变。

网页新增内部反馈 `POST /api/media/events`，由播放器页面自动调用，不交给中控模拟。每次装载媒体生成独立会话标识；报告还必须匹配当前播控版本，迟到、重复、旧点位或暂停/停止前的报告不触发切点。

状态增加：`playbackState=ended`（视频已播完）、`showing`（无视频/图文）、`mediaError`（媒体异常）、`mediaSessionId`（内部关联标识）。到位更新不更改播控版本或重新装载视频。

## 6. 软停、验证与交付边界

新增 `POST /api/control/emergency-stop`。它会停止自动巡展、取消本程序尚未完成的移动，再向厂家软件的UDP53500发送协议中的 `STOP`。

- 厂家文档将 `STOP` 定义为软停：保持使能，并按当前减速度减速至0；它不是断电、断使能或安全回路。
- 现场遇到人身/设备风险仍应优先使用厂家控制界面的使能/急停和现场安全措施；软件按钮不能替代硬件安全急停。
- 中控8001同样可调用此接口，但应设置二次确认，且绝不因请求超时自动重发。

本机使用内存模拟电机与独立假控制器，验证结束/到位的两种顺序、混合图文计时、暂停停止、旧反馈过滤、停止巡展不取消在途动作、单点重播、回原点巡展、软停只发一次和错误不重发。HTTP回归验证数字人协议及原中控接口兼容。没有连接现场硬件。

V1.1.5包含受保护的中控入口TCP8001，原本机数字人入口8000不变；中控须使用独立密钥，允许中控侧自行持久化保存。现场旧包须更新才获得这些改动；本次不修改现场文件或防火墙。密钥、远程地址和配置步骤见《中控平板接入交接-青藏高原滑轨屏.md》。模拟无法代替真实浏览器解码、触屏、长时间运行效果验证。
