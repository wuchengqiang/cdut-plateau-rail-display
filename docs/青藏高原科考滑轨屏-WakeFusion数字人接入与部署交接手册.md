> 版本：2026-09-11，应用修订 1.1.3（同机 UDP、正坐标、边移动边播放、数字人预留布局）
>
> 应用 ID：`cdut-slider-screen`
>
> 协议：WakeFusion 嵌入应用 V1.1（`wakefusion.embedded-app/v1`）
>
> 本文是本项目数字人接入、部署和现场联调的唯一交接依据。

## 1. 交付内容

交付给数字人团队：

- `WakeFusion滑轨屏-UDP双模式版-V1.1.3-20260911.zip`
- 本交接手册
- 参考协议：`第三方对接标准/WakeFusion嵌入应用开发与部署约定V1.1.md`

应用包 SHA-256 见同目录的 `.zip.sha256` 文件。

应用包根目录包含固定的 `app` 目录和本交接手册。它是本机 Web 服务，不需要 Tauri，支持独立全屏与数字人托管两种启动方式。不要同时运行两种模式。

## 独立现场调试（先用这个）

1. 完整解压本包，保留 `app` 内全部文件；独立运行不要求旁边有 Host。
2. 关闭数字人 Host、旧版独立服务和开发预览，避免占用 8000 端口。
3. 在同一台电脑上启动厂家控制软件，确认已启用 UDP 53500、下游电机驱动连接正常。本程序发送到 `127.0.0.1:53500`，不是直接连接电机。
4. 双击 `app/start-standalone.bat`。程序自动启动服务，待页面服务就绪后自动用 Microsoft Edge 全屏打开 `http://127.0.0.1:8000/`。不需要手工输入网址，也不需要数字人的 Token。电脑需安装 Microsoft Edge。
5. 页面会按当前浏览器的有效分辨率适配。竖屏请先在 Windows 显示设置中选择正确的屏幕方向和分辨率；点位自右向左排列，窄屏自动换行。浏览器全屏不是视频全屏，页面仍显示点位和播放控制。
6. 管理员密码 `2468`，先点“硬件 Ping”。**如果零点仍临时设在轨道中间，不要直接点击点位按钮。** 先核实最终零点、限位及四个点位坐标，必要时修改 `app/runtime/config/points.json` 并重启。确认场地安全后点击“高原启程”，视频立即播放，同时发送 `MOVE 1600`；到位回执只更新机械状态。测试暂停、继续、音量，不要先开启自动巡展。
7. 测试完成、滑轨停止后，按 `Alt+F4` 关闭全屏网页，程序会停止独立服务。也可以关闭服务命令窗口。退出程序不等于电机急停。
8. 如果提示端口占用，先退出上次的服务或 Host，再重新双击。不要开多个实例；如果提示找不到 Edge，请先安装 Microsoft Edge。

独立模式使用 `runtime/browser-profile` 专用浏览器目录，不改动日常 Edge 配置。自动全屏采用 [Microsoft Edge 官方 kiosk 模式](https://learn.microsoft.com/en-us/deployedge/microsoft-edge-configure-kiosk-mode)。

## 2. 数字人 Host 部署步骤（后续联调）

1. 停止部署电脑上的 WakeFusion Host。
2. 解压本次 1.1.3 应用包（对接标准版本仍为 V1.1）。
3. 将解压得到的 `app` 文件夹整体放入 WakeFusion Host 根目录；如已有旧 `app`，先备份再整体替换。不要混用新旧 EXE 和 `_internal`，也不要用旧版 `machine.json` 覆盖新版 UDP 配置。现场自定义文字、动作关键词、素材等从备份逐项迁移。
4. `app/runtime/config/admin.json` 的默认管理员密码是 `2468`；如需修改，密码不得少于 4 位。
5. 确认目录层级：

   ```text
   <WakeFusion Host目录>\
   ├─ wakefusion-terminal-host.exe
   └─ app\
      ├─ app.json
      ├─ start.bat
      ├─ start-standalone.bat
      └─ runtime\
         ├─ slider-screen-service.exe
         ├─ _internal\
         ├─ config\
         └─ content\
   ```

6. 启动 WakeFusion Host。Host 检测页面不可访问时，会隐藏运行 `app/start.bat` 并等待健康检查通过。
7. Host 加载页面和动作目录后，数字人可按最新动作目录调用。实际数字人的形象、位置与授权由 Host 配置；仅把本应用放入目录，不会自动生成数字人。机械动作须先完成第 9 节安全确认。

`start.bat` 仍带 `--no-browser`，不会弹出独立浏览器；不要将 Host 的启动文件改成 `start-standalone.bat`。双击 `runtime/slider-screen-service.exe` 则默认独立全屏模式，日常建议使用独立启动脚本以便查看失败提示。

启动脚本为纯 ASCII、CRLF 换行，不必手工另存为 ANSI。不要先启动开发服务占用 8000 端口。

## 3. Token 与安全边界

- Host 必须通过进程环境变量传入 `WAKEFUSION_APP_TOKEN`。
- Host 调用四个 V1 接口时必须携带：

  ```http
  Authorization: Bearer <WAKEFUSION_APP_TOKEN>
  ```

- Token 不得写入 `app.json`、前端、配置文件、URL、日志或交接消息。
- 应用仅监听 `127.0.0.1:8000`；数字人不接触控制器 IP、端口、点位坐标和底层通讯报文。
- WakeFusion 只能调用本手册列出的 V1 接口，不能直接调用项目内部 `/api/control/*` 接口。

## 4. 页面地址与标准接口

嵌入页面：

```text
http://127.0.0.1:8000/?embed=1&avatarAnchor=right
```

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| `GET` | `/api/wakefusion/v1/health` | 健康检查，`ready=true` 后加载页面 |
| `GET` | `/api/wakefusion/v1/status` | 当前展项、播放状态及 `actionsHash` |
| `GET` | `/api/wakefusion/v1/actions` | 获取当前启用的动作数组 |
| `POST` | `/api/wakefusion/v1/actions/{index}/execute` | 按当前动作数组的 0 基索引执行 |

执行请求必须同时提供相同的 `requestId` 与 `Idempotency-Key`。同一幂等键的重复请求不会再次产生机械或播放副作用；写操作失败时 Host 不应自动重试。

## 5. 当前动作目录

当前全部动作启用时，动态索引如下：

| 当前索引 | 动作 | 结果 |
| ---: | --- | --- |
| 0 | 高原启程 | 切换到 `p01` |
| 1 | 地质巡测 | 切换到 `p02` |
| 2 | 冰川源区 | 切换到 `p03` |
| 3 | 高原守望 | 切换到 `p04` |
| 4 | 播放 | 播放或继续当前视频 |
| 5 | 暂停 | 暂停当前视频 |
| 6 | 停止 | 停止视频并回到开头 |
| 7 | 返回首页 | 停止巡展并返回机械原点 |
| 8 | 开始自动巡展 | 按展项顺序自动切换 |
| 9 | 停止自动巡展 | 停在当前展项 |

V1.1 索引不是永久编号，而是 `/actions` 当前启用数组的位置。禁用一个动作后，后续索引会前移；Host 必须以最新 `/actions` 响应为准，不得缓存旧索引长期调用。应用状态中的 `actionsHash` 会在公开文字、启用状态或顺序变化时改变，Host 每 5 秒轮询状态并重新拉取动作目录。

## 6. 动作配置页面

管理员在本机访问：

```text
http://127.0.0.1:8000/subscriptconfig.html
```

登录后可以修改动作名称、说明、正向关键词、反向关键词和启用状态。页面会显示保存后的动态索引并自动生成新的 `actionsHash`；不能修改内部处理器、点位目标或排序。

为避免配置保存和机械动作产生索引竞态，只能在滑轨静止、自动巡展停止且视频未播放时保存。不要直接编辑 `config/wakefusion.json`。

## 7. 页面嵌入行为

- 左侧约 70% 为展项介绍、16:9 视频框、触控按钮和点位；右侧约 30% 持续预留给 Host 的真实数字人。视频等比例完整显示，不裁切；竖版视频会留边。
- `embed=1` 时隐藏本页玩偶、管理员入口和独立预览的占位说明。默认 `avatarAnchor=right`；`avatarAnchor=left` 可镜像布局。Host 需将数字人放在对应预留区，实际大小需现场联调。
- 本页装饰玩偶默认关闭：`config/app.json` 的 `"showMascots": false`；没有此字段也默认关闭。改为布尔值 `true` 只在非嵌入模式显示，不影响 Host 真实数字人。
- 页面保留点位触控、播放/暂停/停止、静音/音量和左右滑动切换。
- 左滑按 `p01 → p02 → p03 → p04` 切换，同时发送对应点位移动命令；视觉导航从右到左排列 `01 → 02 → 03 → 04`。
- 选点后立即播放，再等待电机到位；移动途中可暂停或停止视频，到位后不会重新播放。移动未完成时拒绝新的点位切换，避免并发移动；硬件错误在视频下方提示，不模糊遮挡视频。
- 已移除视频全屏入口，数字人区域一直保留。独立启动的 Edge 整页全屏仍保留，两者不同。
- 不使用浏览器弹窗、新窗口、下载或全屏 API，满足 Host 沙箱约束。

## 8. 联调验收

- [ ] Host 启动后应用在 30 秒内被自动拉起，现场没有手工启动服务。
- [ ] 健康接口返回 `ok=true`、`ready=true`、`version="1.1.3"`（应用版本，标准仍是 V1.1）。
- [ ] `/actions` 返回数组，条目不含 `index` 和 `revision`。
- [ ] `/status` 返回 64 位十六进制 `actionsHash`。
- [ ] 数字人位于右侧且不遮挡关键触控区。
- [ ] 核实原点、行程、各点位及素材后，再逐项测试动作；目前只有点位 1 视频，不要直接测试自动巡展。
- [ ] 选点后视频在电机到位前开始播放，移动途中暂停后，到位不会自动恢复；右侧预留区不被控件遮挡。
- [ ] 相同幂等键重复调用不重复执行。
- [ ] 非法状态返回 `409 action_conflict`，鉴权失败返回 `401 auth_failed`。
- [ ] 修改一个动作文字或启用状态后，Host 能根据新哈希重新加载动态索引。

## 9. 现场机械启用

> 本次交付包已按厂家确认启用 `runtime/config/machine.json` 的 `provider: "udp"`，点位按钮及数字人点位动作会驱动真实滑轨。

1. 同机厂家网络控制软件/服务必须启动并启用 UDP 53500；其下游驱动连接应正常。单有电机通电不等于网络接口已运行。`127.0.0.1` 指运行播放器的电脑；如果以后分到不同电脑，需要改成厂家软件所在电脑的实际 IP。
2. 现场确认急停、限位、方向、原点、净空和控制器通讯。
3. 在管理员面板点“硬件 Ping”验证是否返回 `PONG`。不需要移动滑轨；Windows 的 `Test-NetConnection -Port` 只测 TCP，不能判断本次 UDP 是否可用。
4. 核实正式坐标后重启服务，再测试点位 1（手动点击“高原启程”，或通过数字人当前动作目录调用）。视频应立即播放，机械位置必须等收到目标坐标的到位回执才更新。其余点位缺少视频时不要启动自动巡展。
5. 未完成机械安全确认前，禁止用数字人语音驱动真实滑轨。

本包预置参数：厂家软件 UDP `127.0.0.1:53500`；原点 `0 mm`；展示点依次为 `1600`、`3200`、`4800`、`6400 mm`；SharedKey 为空，客户端白名单未启用。坐标为有符号的绝对毫米值，发送时不会取反；`MOVE 100` 表示去绝对 +100，而非在当前位置前进 100。

**现场 +100 测试只确认了正负号含义，没有重新确认这四个正式展示点。若零点仍在中间，必须先核实最终原点与每个展示点，避免超出行程。程序启动不会替厂家软件设零。**

本版使用 ASCII 文本 UDP 请求/响应，命令以 CRLF 结尾，不发送仅支持 TCP 的 `WATCH/UNWATCH`。选点立即播放并发送 `MOVE <mm>`，收到对应坐标的 `OK:MOVE <mm>` 才更新已到位状态，等待上限 60 秒。UDP 丢包或超时不会自动重发移动命令；先确认实际位置、控制器状态后再决定是否重试。页面“停止视频”及关闭软件都不等同于机械急停，请使用现场硬件安全设施。

`displayPointId` 表示正在展示的内容；`targetPointId` 表示等待到位的目标；`currentPointId` 表示上次确认的点位，启动初始值不是传感器实测位置。视频播放成功或页面健康都不代表电机到位。

本包包含点位 1 的 `runtime/content/videos/p01.mp4`，点位 2～4 视频尚缺。点位文字与路径可配置。软件编译与本地模拟测试不能替代现场真实滑轨、触屏分辨率和 Host 数字人叠加验收。

1.1.1 已解除“页面就绪必须等待控制器初始化”的依赖：业务配置加载后健康接口即可返回 200。硬件初始化在后台进行，上限 15 秒，故障通过 `/status` 报告；连接期间点位动作返回 `423 application_busy`。页面就绪不代表滑轨已连接或已到位。

## 10. 现场可配置项

| 位置 | 可配置内容 | 生效方式 |
| --- | --- | --- |
| `runtime/config/app.json` | 标题、主题、按钮文字、校徽、玩偶路径及 `showMascots` 开关 | 管理员重载或重启 Host |
| `runtime/config/points.json` | 点位名称、视频、介绍、坐标和素材 | 管理员重载或重启 Host |
| 动作配置页面 | 动作文字、关键词、反向关键词和启用状态 | 保存后哈希自动变化 |
| `runtime/config/machine.json` | `mock/tcp/udp` 和控制器网络参数（本包 udp） | 重启 Host |

视频放在 `runtime/content/videos`，并在 `points.json` 中配置对应路径。点位按钮名称、页面文字和动作提示均不需要写入前端代码。

配置文件用 UTF-8 保存，JSON 的文字与路径用双引号；数字和布尔值不加引号。管理员密码文件的完整示例为 `{"password":"2468"}`，它只用于本页管理员登录，不是 Host Token，也不是厂家 SharedKey。

## 11. 常见问题

| 现象 | 优先检查 |
| --- | --- |
| Host 未加载页面 | `app` 层级、`app.json` UTF-8 编码、`start.bat` 和启动超时 |
| 健康接口返回 401 | Host 是否传入并携带 `WAKEFUSION_APP_TOKEN` |
| 健康接口持续 503、正在加载业务数据 | 核对是否仍在运行旧程序；本版应报告 1.1.3。停止 Host 后确认旧业务服务退出，再整体替换 app，由 Host 重新启动 |
| 数字人没有动作工具 | 页面 metadata、`ready`、动作授权和 `actionsHash` |
| 修改动作后未生效 | 是否从配置页保存；Host 是否检测到新 `actionsHash` 并重新获取 `/actions` |
| 动作索引调用错误 | 必须使用最新启用动作数组的 0 基位置，不能使用旧固定编号 |
| 页面正常但滑轨不动 | 是否为 `udp`；厂家 UDP 服务、IP/端口、防火墙、下游驱动连接及机械安全条件。PONG 只证明网络服务响应，不证明电机可运动 |

## 12. 交付结论

本应用按 WakeFusion 嵌入应用 V1.1 的 `service` 模式交付，不是 Tauri 安装包，也不需要另装 Python。数字人团队由 Host 启动服务、加载页面与动态动作目录，并确认真实数字人位于预留区；现场人员负责最终坐标和安全验收。
