# 现场部署：数字人 + 滑轨播放器 + 中控

这是Web服务绿色包，不是Tauri安装包。无需现场安装Python或Node.js。**通用包不包含任何视频文件**；现场按点位配置自行复制视频。没有视频的点位展示图片/文字，自动巡展到位后停留12秒。

> 本文适用于V1.1.5及以后版本：包含“静态演示/隐藏点位栏/正常参观”、`1→2→3→4→3→2→1→0` 巡展和软件软停。

## 1. 更新前先保留现场资料

停止Host和旧播放器。备份旧 `app/runtime/config`、`app/runtime/content`，特别是已存在的 `config/remote-control.key`。首次使用8001入口的旧版本没有该密钥文件是正常的。

不要直接删掉唯一一份旧app。先将旧app改名为备份目录，再放入新版app。新包配置已经是：厂家软件UDP `127.0.0.1:53500`，原点0、四点正坐标1600/3200/4800/6400；如果现场另有实际修改，以备份配置为准，逐项核对，不要覆盖丢失。

从备份恢复现场图片/视频及已修改的点位、文案等配置；保留新版新增的 `remote-control.json`，不要用整个旧config目录覆盖后导致新配置丢失。已有 `remote-control.key` 必须原样复制到新版 `app/runtime/config/`。

视频必须由现场人员复制到新版目录，不随本包携带：

```text
app\runtime\content\videos\p01.mp4
app\runtime\content\videos\p04.mp4
```

文件名不是接口约束；它必须与 `app\runtime\config\points.json` 对应点位的 `videoPath` 一致。当前默认p01、p04分别配置为 `content/videos/p01.mp4`、`content/videos/p04.mp4`。

## 2. 放到正确目录并启动

```text
C:\数字人\
├─ host\
└─ app\
   ├─ app.json
   ├─ start.bat
   ├─ start-standalone.bat
   └─ runtime\
      ├─ slider-screen-service.exe
      ├─ _internal\
      ├─ config\
      └─ content\
```

- 和数字人联动：启动Host，由Host读取同级app并运行 `start.bat`。不要同时再开独立播放器。
- 单独调试：保持厂家软件运行，双击 `app/start-standalone.bat`，自动用Edge全屏打开页面；Alt+F4关闭独立页面及其服务。电脑需安装Microsoft Edge。
- 两种模式都有本机8000入口和受保护中控8001入口，只运行一份即可。启动提示端口占用时先关闭重复程序，不要反复叠加启动。
- BAT文件已统一ASCII内容、CRLF换行，不需要再用记事本另存ANSI。
- 本机页面仍为 `http://127.0.0.1:8000/`；数字人的原app.json和pageUrl结构保持兼容。
- 管理员密码默认 `2468`，只用于页面管理，不是中控密钥。

## 3. 中控接入

1. 新版首次启动自动生成 `app/runtime/config/remote-control.key`。打开文件，将整行密钥配置给中控；不要多加引号。
2. 中控地址填 `http://192.168.1.105:8001`，每个请求带 `Authorization: Bearer 实际密钥`。中控已确认支持POST空请求体和GET查询。
3. 中控可持久化入库保存密钥，安全存储及版本升级保留由中控侧负责。播放器升级保留原密钥文件即可；新包不内置统一密钥，不自动轮换已有值。
4. 在可信现场网络上，确认Windows网络配置为“专用”。以管理员PowerShell放行必要的中控来源；下例允许当前192.168.1.x局域网，确定中控后台IP后可收紧：

```powershell
New-NetFirewallRule -DisplayName "Rail-Central-TCP-8001" -Direction Inbound -Action Allow -Protocol TCP -LocalPort 8001 -RemoteAddress 192.168.1.0/24 -Profile Private
```

程序不会自动改防火墙。已有同名规则则检查/更新，勿重复创建。中控实际来源不在该网段时，须同时修改 `remote-control.json` 的 `allowedClients` 和防火墙来源。不要关闭整个防火墙，不要将端口映射到公网。

5. 先让中控带密钥GET `/api/status`、`/api/points`，都是只读，不移动机械；连通后再由人在场确认点位或播控动作。

仅放行8001，不把本机8000、厂家UDP53500当作中控入口。8001不提供播放器网页或管理员页面，直接在浏览器打开其根地址被拒绝是预期行为。完整接口见同包《中控平板接入交接-青藏高原滑轨屏.md》。

## 4. 自动巡展和常见问题

- 有视频：开始移动时就播放，视频播完且确认到位后才切下一点；视频暂停/停止不会被误判为播完。
- 无视频/图文：确认到位后统一停留，秒数在 `config/app.json` 的 `carouselDwellSeconds`，默认12。
- 默认巡展从当前位置继续递增至p4后折返，并最终回原点停止；例如当前在p2，顺序是 `p03→p04→p03→p02→p01→p00`。
- `config/app.json` 的 `presentation.mode`：`demo` 为明日静态演示（隐藏底部点位和标题编号、禁用切换），`compact` 隐藏底部点位但保留半透明箭头/左右滑动，`visit` 恢复完整参观界面。当前默认是机械停p4、展示p1：`demoRestPointId=p04`、`demoContentPointId=p01`。
- 管理员面板可直接切换展示方式；“前往p4演示位置”需二次确认，并在到位后恢复p1内容。只编辑配置或刷新页面不会自动移动机械。
- 移动异常退出巡展、不重发动作；停止巡展只停止后续排程，不是急停。页面“紧急停机（软停）”和中控 `POST /api/control/emergency-stop` 发送厂家协议 `STOP`，保持伺服使能、按减速度停下；它不能替代厂家控制软件的硬件急停/使能控制。
- 401是缺少/错误的中控密钥；403检查来源地址、Origin或接口路径；405检查GET/POST；网络超时检查是否新版、程序启动、IP、端口与防火墙。
- 更换素材或配置后重启。主机网页必须保持运行，只有后端没有页面不会播放视频或产生视频结束反馈。
- 升级后突然401：检查是否丢失原密钥并生成了新值，恢复原文件后重启或同步更新中控保存值。中控数据库保留旧密钥不能替代播放器端文件的备份。

程序回归使用隔离副本与本机模拟/假UDP控制器，不连接现场电机。实际局域网和浏览器解码/长时间播放仍需部署后确认，已测好的机械坐标不因接口升级重新测量。
