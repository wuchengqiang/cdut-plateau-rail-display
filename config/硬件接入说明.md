# 滑轨控制器接入说明

本程序已按《信捷伺服控制系统 - 通讯协议（TCP/UDP）》实现真实硬件提供者，默认仍为安全的 `mock` 模式，不会发送任何硬件指令。

## 上线前必须填写

编辑 `config/machine.json`：

1. 将 `provider` 改为 `tcp`（推荐，支持 `WATCH` 实时位置）或 `udp`。
2. 填写 `network.host` 为控制器实际 IP；端口默认 `8080`，如设备界面修改过则同步修改。
3. 填写 `positionsMm.P1` 至 `P4` 的实测绝对毫米坐标。程序将 `P1` 作为回原点目标。
4. 若控制器启用 `SharedKey`，填写相同的 `network.sharedKey`；程序会自动发送 `KEY <密钥>;命令`。

示例（仅结构示例，坐标和 IP 必须来自现场，不可照抄）：

```json
{
  "provider": "tcp",
  "positionsMm": { "P1": 0, "P2": 1250, "P3": 2500, "P4": 3750 },
  "network": { "host": "192.168.x.x", "port": 8080, "sharedKey": "" }
}
```

## 已实现的协议行为

- 启动时 `PING`，并通过 `STATUS` 获取 `POS / ALM / RDY`。
- 切换场景时发送 `MOVE <毫米>`；控制器返回 `OK:MOVE`（已到位）后才播放视频。
- TCP 模式启动 `WATCH 100` 接收 `POS:<值>mm`，UDP 按协议不使用 `WATCH`。
- 取消场景或停止时发送 `STOP`。这是协议定义的软停，不会自动断使能。
- “回原点”使用已配置的 P1 绝对坐标，绝不调用 `ZERO`，避免意外改变控制器坐标系。

## 首次通电联调

完成配置后，先调用 `POST /api/admin/hardware/ping`，确认返回 `PONG`；再调用 `GET /api/admin/hardware/status` 检查是否存在 `ALM` 告警。确认空载和安全范围后，才可从场景 1 开始逐点试运行。
